Use brand discovery to help shoppers find a designer, learn about a brand, and browse its products. A brand describes who makes or designs a product. It is distinct from the stores and sellers that carry it.

## Choose a starting point

- Build an A–Z list with the complete [brand directory](/api-reference/brand-directory).
- Find a brand from a description, reference brands, or filters with [Brand Search](/api-reference/search-brands).
- Complete part of a name with [prefix search](/api-reference/brand-prefix).
- Find alternatives with [similar brands](/api-reference/similar-brands).

```bash
curl https://api.storerouter.ai/v1/brands/search \
  -H "Authorization: Bearer $STOREROUTER_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"q":"minimalist footwear made with natural materials","similar_to_brands":["Allbirds"],"limit":12}'
```

Search returns `totalFound` and ranked `results`. Each result includes `brandUuid`, `brandName`, `brandSlug`, `domain`, `brandDescription`, and `directorySubheading`. Optional metadata can be null. Use the returned slug, or the canonical name when the slug is null, as the identifier for the next request.

## Render a brand page

Read the lightweight [profile](/api-reference/get-brand) for public metadata, typed article cards, and navigation facets. Use the returned canonical identity for your page URL. Keep article dates at their actual precision, such as `May 2026`.

Build navigation with the normalized `gender`, `age_groups`, and `category_path.depth_*` facets. Labels and combinations belong to your application. The [top-categories endpoint](/api-reference/brand-top-categories) also provides precomputed category metadata. Both describe the brand's recorded assortment across the corpus; neither promises live products in your customer's scope.

Request the separate [coverage snapshot](/api-reference/brand-coverage) when you need approximate product counts, carrying catalogs, facet coverage, or price distributions. Render the profile even if that request fails.

## Browse products

Use [brand product browsing](/api-reference/browse-brand-products) for a consistent UUID-ordered grid. Follow the returned `nextOffset` until it is null, including when the projected products list is empty. Offset 11976 is the last supported start, equivalent to page 500 at 24 rows per page. Use Product Search for text, additional filters, and relevance ranking.

Directory, profile, navigation, top categories, and coverage are corpus-wide metadata. Product rows and browse source totals respect your API key's catalog scope. An explicit empty scope returns no products. A brand match, category, or approximate coverage count does not grant product access.

## Handle missing data and failures

Every REST operation requires your Developer organization API key. Keep credentials on your server. The directory has a one-hour private cache and ETag revalidation. Coverage is an independently cached snapshot.

Treat `404 brand_not_found` as a missing identity. Treat `503` as an operational failure, not an empty directory, absent articles, or a missing brand. Empty article and category lists are valid successful results. Validation failures return `422`; missing or invalid credentials return `401`; forbidden organizations return `403`. The standard organization [rate limit](/guides/rate-limits) applies.

## Brand filters and SDKs

Brand Search accepts `q`, `similar_to_brands`, `facets`, `exclude_facets`, `understand`, and `limit`. Omit `q` for reference- or filter-only requests. Without text, query understanding is skipped. Explicit clauses are preserved and never relaxed. Set `understand: false` to use text as written.

Brand filters use `{name, values}` with names such as `facet_price_tier`, `facet_origin_country`, `facet_styles`, `facet_genders`, and `facet_category_path.depth_0` through `facet_category_path.depth_6`. These differ from the Product Search names in profile navigation. Each inclusion or exclusion list supports up to 20 clauses, with 1–100 nonblank values per clause and 256 characters per value. Product-only filters and internal quality controls are rejected. The separate similarity operation retains `brands`, `facets`, and `exclusionFacets`.

Use the [Python SDK](/sdks/python#brand-directory-profiles-and-browsing), [TypeScript SDK](/sdks/typescript#brand-directory-profiles-and-browsing), or [CLI](/cli/overview#discover-and-browse-brands) for typed examples. The canonical operation names are listed on each reference page.

The [StoreRouter MCP connection](/mcp/overview) exposes `search_brands`, `similar_brands`, `brand_prefix`, `get_brand`, `browse_brand_products`, and `get_brand_top_categories`. `get_brand` returns the profile. Use REST or an SDK for the separate coverage snapshot. Developer callers omit `org_id`; internal super admins select an organization without expanding their own product scope.
