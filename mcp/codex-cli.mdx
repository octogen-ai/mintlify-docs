Codex CLI connects to the same StoreRouter MCP server as every other client, `https://mcp.dev.storerouter.ai/mcp`. You register the server, sign in once in your browser, and Codex caches and refreshes the tokens for you. No API keys, client IDs, or manual credential management are required.

<Warning>
  The Codex compatibility hosts, `codex-mcp.storerouter.ai` and `codex-mcp.octogen.ai`, are removed. If your Codex config still points at either host, follow the steps below to replace the entry.
</Warning>

<Steps>
  <Step title="Remove an old registration">
    If you registered StoreRouter with Codex before, remove the existing entry:

    ```bash
    codex mcp remove storerouter
    ```

    If you added the entry by hand, delete the `[mcp_servers.storerouter]` table from `~/.codex/config.toml` instead. Skip this step for a new setup.
  </Step>

  <Step title="Register the StoreRouter MCP server">
    Run the following command in your terminal:

    ```bash
    codex mcp add storerouter --url https://mcp.dev.storerouter.ai/mcp
    ```

    This registers a server named `storerouter` in your Codex configuration.

    Alternatively, add the entry manually to your Codex config file at `~/.codex/config.toml`:

    ```toml
    [mcp_servers.storerouter]
    url = "https://mcp.dev.storerouter.ai/mcp"
    ```
  </Step>

  <Step title="Sign in to StoreRouter">
    Start the OAuth sign-in flow:

    ```bash
    codex mcp login storerouter
    ```

    Codex opens a browser tab with the StoreRouter sign-in page. Complete the sign-in flow:

    1. Enter the email that belongs to your Developer organization.
    2. Authenticate using your organization's configured method (password, SSO, or magic link).
    3. If your account belongs to multiple organizations, select the Developer organization you want to act as.
    4. Consent to the requested scopes.

    After you complete sign-in, the browser redirects back to Codex, which stores the resulting tokens locally.

    <Note>
      Access tokens are valid for approximately five minutes. Codex refreshes them transparently. You are not prompted again unless your StoreRouter sign-in session expires.
    </Note>
  </Step>

  <Step title="Verify the registration">
    Confirm the server is registered with the correct URL:

    ```bash
    codex mcp get storerouter
    ```

    The output should show `url = "https://mcp.dev.storerouter.ai/mcp"`. If it shows a `codex-mcp` host, repeat the first two steps.
  </Step>
</Steps>

## Troubleshooting

- **Codex can't connect, or reports a DNS or TLS error.** Your entry still points at a removed `codex-mcp` host. Remove it and register `https://mcp.dev.storerouter.ai/mcp`.
- **Codex reports an invalid token.** Tokens issued before November 5, 2026 carry a retired audience and are rejected. Run `codex mcp login storerouter` again.

## What your agent can do

Once connected, your agent can use these tool groups:

- **Products**: `lookup_product` and `lookup_products` resolve product page URLs to full product records; `search_products` searches across all covered stores, with optional catalog, facet, price, store, and brand-style filters.
- **Taxonomy**: `taxonomy_tree` and `taxonomy_attribute` find the category and attribute filters that search accepts.
- **Brands**: `search_brands`, `similar_brands`, `brand_prefix`, `get_brand`, `browse_brand_products`, and `get_brand_top_categories`.
- **Stores**: `search_stores`, `similar_stores`, and `get_store` find retailers and describe what they sell.
- **BigQuery**: subscription tools for organizations with BigQuery access.

For arguments and error codes, see the [MCP overview](/mcp/overview#available-tools).
