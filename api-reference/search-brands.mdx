---
title: "Search brands"
description: "Discover brands from a description, reference brands, or explicit filters."
---

Use `POST /v1/brands/search` to find brands that fit a shopper's needs. Send `Authorization: Bearer <your-api-key>` and `Content-Type: application/json`.

```bash
curl https://api.storerouter.ai/v1/brands/search \
  -H "Authorization: Bearer $STOREROUTER_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"q":"minimalist footwear","similar_to_brands":["Allbirds"],"limit":12}'
```

The body accepts optional `q` (1–500 characters), `similar_to_brands` (1–20 nonblank names, each at most 200 characters), `facets`, `exclude_facets`, `understand` (default `true`), and `limit` (1–100, default 24). Supply at least one of text, reference brands, inclusion filters, or exclusion filters. Unknown fields return `422`.

With text, understanding can rewrite retrieval text and generate brand facets. Set `understand: false` to match `q` as written. Without `q`, understanding is skipped. Explicit clauses are preserved and never relaxed; filter-only ordering is unspecified. Use the [directory](/api-reference/brand-directory) for a complete alphabetical list.

The response contains `totalFound` and ranked `results`. Each result includes `brandUuid`, `brandName`, `brandSlug`, `domain`, `brandDescription`, and `directorySubheading`. Metadata can be null. Errors include `400 brand_query_unusable`, `400 brands_have_no_embeddings`, and `503 brand_search_unavailable`.

See [Discover brands](/guides/brand-discovery) for filters, scope, profiles, and product browsing.
