---
title: "Browse brand products"
description: "Browse active brand products within your authorized catalog scope."
---

`GET /brands/{brand}/products` browse active brand products within your authorized catalog scope.

Send `Authorization: Bearer <your-platform-api-key>` with every request. POST requests also require `Content-Type: application/json`. Use the base URL `https://api.storerouter.ai/v1`.

URL-encode the brand slug or case-insensitive name in `brand`. Optional query parameters: `limit` (1–100, default 24), and `offset` (0–10000, default 0).

```http
GET https://api.storerouter.ai/v1/brands/allbirds/products?limit=24&offset=0
```

Returns `brandName`, `brandSlug`, `products`, `total`, `limit`, `offset`, and `hasMore`. Products use the same `MerchantProductListItem` shape as [product search](/api-reference/search-products). `total` counts active rows within your catalog scope before malformed rows or rows without a usable URL are dropped. A page can contain fewer than `limit` items even when more rows exist.

When `hasMore` is true, advance `offset` by `limit`. Pagination stops when the next offset would exceed 10000, even if `total` is larger. Unknown brands return `404` with `brand_not_found`; a known brand with no accessible products returns an empty page.

See [Discover brands](/guides/brand-discovery) for brand-versus-store semantics, catalog scope, filter rules, MCP equivalents, and shared authorization, validation, and rate-limit errors.
